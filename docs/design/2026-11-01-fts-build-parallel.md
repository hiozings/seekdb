# 全文索引构建：采样与并行流水线

开发基点为已推送到两个远端的 `7301a84bf`。官方基准的数据、SQL、计时与评分规则保持原样。

## 定位依据与选择

- 前一轮按文档批处理已落地，继续优化逐字符解码、字典直查、缓存重放分配未得到稳定的附加收益。
- 新增 CPU 诊断发现两张辅助索引会重复解析相同文档。缓存填充锁通过并发正确性测试，但六轮同机测试使构建平均退化约 5.80%，因此撤回。
- 对短函数进行嵌套线程 CPU 时钟采样会放大计时开销，进一步改用低开销时钟、错开的采样位置并避免嵌套计时。结果表明排序和写入仍有可观开销；各阶段包含调用子阶段，不能直接相加当作墙钟耗时。
- 代码中默认 DDL 并行度为 1，FTS 辅助构建还经过 `/3` 限制。采样扫描跳过 FTS 词行展开，doc-id 域在采样时填空值；这种采样键不代表实际索引键，可能造成并行分片不均衡。
- 参考公开实现 [PR #2219](https://github.com/oceanbase/seekdb/pull/2219) 的默认并行和真实采样键方案，并适配本分支已启用的批处理路径。

## 实现

1. 为 DDL 参数增加默认并行标志，覆盖初始化、reset、assign 和序列化。仅对允许并行且没有有效显式并行设置的 FTS DDL 标记；SQL hint、强制 DOP、索引 DOP、禁用并行及非 FTS 路径保留原决策。
2. 两张主要全文辅助索引使用 `min(2, max(1, cpu_count / 2))`，读取实例配置核数。两核默认不变，四核各启用 DOP 2；doc-id 与主键映射表的策略不变。
3. 采样行也展开为真实词行。按源表完整主键点查对应 doc-id，域表点查自身不再采样，避免用另一条域表记录配对。
4. 对批量采样，域合并每次返回一个源文档，使用 batch index 0；上一轮的 FTS 文档批处理继续负责词行展开和文档内存生命周期。
5. 采样展开不写入已有默认关闭的 compact collector；真实扫描继续保留原收集行为。

## 验证与测量

- 新增任务参数标志的 native 序列化回归。
- 录制并比较 674 项完整输出：原有分词/检索/DML/批边界用例，加 4096 行乱序插入、复合主键、分区表、IK/BENG、显式/默认并行配置、ANALYZE、空表建索引及后续 DML。
- 10 个 native 目标与 9 组官方 SQL 回归通过。性能结果单独记录，不以命中数代替完整结果验证。
- 四核 A/B 使用相同的实例核数、内存、亲和性和官方参数。用户已授权临时调整 CPU 8/10/14/16 governor 并恢复；测试工具保存前后状态，额外用模拟失败测试检查部分设置失败及基准失败后的恢复行为。
- 同机相对原始二进制的下降比例与正式平台分数分别报告，不将不同核数的基线和候选混算。
