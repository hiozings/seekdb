# MiniVectorDB 简要设计

> 状态：M0（协议层 + SQL 解析 + 内存执行骨架）。标「计划」的章节在 M1–M5 落地。

## 1. 目标与范围

单机、单进程、单客户端连接、同一时刻最多一个显式事务的轻量向量数据库。
数据与恢复所需文件一律位于 `/data`。不提供网络服务，只经 stdin/stdout 交互。

## 2. 分层结构

```
main           进程入口：参数、信号、stdin 循环
  protocol     语句切分、线格式（FormatSpec）、结果/错误渲染、flush
  sql          词法 → 递归下降解析 → AST；错误码
  exec         规划与执行：过滤、投影、排序、TopK、L2 距离、类型强转
  storage      页管理、buffer pool、堆文件、B+tree、catalog      （计划 M1）
  txn          undo、WAL、checkpoint、恢复                      （计划 M3）
  vector       距离核、HNSW、索引工件与版本                      （计划 M4）
```

约束：`protocol` 不依赖 `storage`；`exec` 仅经 `storage`/`txn` 接口访问数据；
线格式的每个可变量都集中在 `FormatSpec`，题包发布后无需改动引擎。

## 3. 记录布局（计划）

- 页大小 8 KiB，槽页存变长记录：`[长度 varint][标志][主键][列值...]`。
- VARCHAR 存 UTF-8 字节（长度上限按码点校验）；VECTOR 存 `dim × 4` 字节连续区。
- 主键索引：磁盘 B+tree（`pk → rid`），保证大于内存预算的数据集也能按主键定位。
- buffer pool 有界（默认 32–64 MiB），使用 `pread/pwrite` 而非 `mmap`：
  内存指标包含页缓存，`mmap` 会把文件全量计入峰值。

## 4. 向量索引方案（计划）

- 算法：自研 HNSW（M=16/32），不引入任何第三方向量索引库。
- `exact` 模式永远暴力扫描（SIMD 距离核），即使存在索引。
- `ann` 模式：
  1. 资格检查：索引存在、`build_key` 匹配、校准表存在；否则退化 `exact` 并记录原因。
  2. 小匹配集（`M ≤ threshold`）直接扫描候选集，等价精确。
  3. 大匹配集走过滤感知 HNSW：**不得"凑够 K 就停"**，必须满足「结果数 = K 且 ef ≥ 校准下限」，
     否则按倍增大 `ef`，仍不足则精确兜底。
- 校准：N 档 × 选择性档，每组取满足平均 Recall@10 ≥ 0.97 的最小 `ef`，
  在独立留出集（≥500 查询）验证，达标门槛 0.98（对官方 0.95 留余量）。

## 5. 事务处理

- M0：`BEGIN` 对整库做快照，`ROLLBACK` 还原，`COMMIT` 丢弃快照；
  每条数据修改语句前做整库快照，保证语句失败无部分生效。
- 计划 M3：物理 undo（前像）+ 行级 overlay，避免快照随数据量线性膨胀；
  允许脏页外刷（steal），大事务不会撑爆内存。

## 6. 提交持久化（计划）

`WAL 追加（CRC32 + LSN）→ COMMIT 记录 fsync → 返回成功 → 数据页懒刷`。
NO-FORCE 策略避免每批重写数据文件；checkpoint 先刷页并 fsync，再截断 WAL 前缀。

## 7. 恢复流程（计划）

```
读 checkpoint → 重放已提交事务 → 丢弃未提交 → 截断 CRC 失败或长度不全的尾部
→ 标记 clean → 装载/重建向量索引 → 打印就绪
```

- 页头携带 `pageLSN`，redo 幂等，保证「恢复途中被强制终止」后再次启动收敛到同一状态。
- 向量索引可从持久化记录重建；重建完成前不得报告就绪。

## 8. 已实现功能（M0）

- 完整 SQL 子集解析：`CREATE TABLE`、`INSERT`（多行）、`SELECT`（投影 / `*` / `L2_DISTANCE` /
  `WHERE` / `ORDER BY` / `LIMIT`）、`UPDATE`、`DELETE`、`BEGIN`/`COMMIT`/`ROLLBACK`。
- 类型校验：`BIGINT`、`VARCHAR(n)`（Unicode 码点计数）、`VECTOR(n)`（float32、拒绝 NaN/Inf/维度不符/溢出）。
- 语义：主键唯一、距离并列按主键升序、过滤后 TopK 在匹配集内计算、语句原子性、事务内读己写。
- 线格式：制表符分隔、可配置表头/分隔符/浮点格式/错误模板/就绪标识。
- 容器：多阶段构建，静态链接 `libstdc++`/`libgcc`，前台运行，无端口。

## 9. 已知限制

- 数据仅存于内存，进程退出即丢失（M1 接入页存储，M3 接入 WAL）。
- 无向量索引，`ann` 模式尚未存在（M4）。
- 事务快照为整库复制，数据量大时开销线性增长（M3 替换为 undo）。
- 排序在内存中完成；超大结果集的 `ORDER BY` 未做外排（视题包用例决定是否实现）。
- 错误码沿用 MySQL 约定，待题包发布后按官方表重映射。

## 10. 设计参考

本地项目 `vecstor-new`（存算分离向量引擎，Python/DuckDB/Faiss）**未复用任何代码**，
其存储/索引/事务建立在赛题禁止的组件上。仅迁移了以下设计经验：

| 迁移点 | 落点 |
| --- | --- |
| "凑够 K 就停"是错误的终止条件 | §4 的 ef 升级与质量下限 |
| 过滤优先 vs 检索优先的分界随选择性反转 | §4 的路径选择与校准表 |
| 校准集 / 留出集分离，选参后冻结 | §4 的校准协议 |
| 索引三版本（数据版本 / 构建指纹 / 发布序号） | §4 的资格检查与退化 |
| 资格与成本分离，未知即退化参考路径 | §4 的退化记录 |
