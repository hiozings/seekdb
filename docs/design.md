# MiniVectorDB 简要设计

> 状态：M4（协议层 + SQL 解析 + 持久化页存储 + B+tree 主键索引 + WAL 崩溃恢复 + HNSW 向量索引）。标「计划」的章节在 M5 落地。

## 1. 目标与范围

单机、单进程、单客户端连接、同一时刻最多一个显式事务的轻量向量数据库。
数据与恢复所需文件一律位于 `/data`。不提供网络服务，只经 stdin/stdout 交互。

## 2. 分层结构

```
main           进程入口：参数、信号、stdin 循环
  protocol     语句切分、线格式（FormatSpec）、结果/错误渲染、flush
  sql          词法 → 递归下降解析 → AST；错误码
  exec         规划与执行：过滤、投影、排序、TopK、L2 距离、类型强转
  storage      页管理、buffer pool、堆文件、catalog、B+tree 主键索引
  txn          undo（内存链）、WAL、恢复、checkpoint
  vector       距离核、HNSW、索引工件与版本                      （计划 M4）
```

约束：`protocol` 不依赖 `storage`；`exec` 仅经 `storage`/`txn` 接口访问数据；
线格式的每个可变量都集中在 `FormatSpec`，题包发布后无需改动引擎。

## 3. 记录布局

- 页大小 8 KiB，槽页：页头 24 字节，槽目录从前往后增长，记录从后往前存放；
  槽为 `(uint16 offset, uint16 len)`，`len == 0` 表示已删除且可复用。
- 行按模式紧凑编码，无逐值类型标签：`BIGINT` 8 字节 LE、`VARCHAR` 长度+UTF-8 字节、
  `VECTOR` `dim × 4` 字节的 float32 位模式。
- 每表一个堆文件 `t<id>.heap`，页按需追加；记录 ID 为 `(page_id << 16) | slot`。
- buffer pool 有界（默认 256 页 = 2 MiB），使用 `pread/pwrite` 而非 `mmap`：
  内存指标包含页缓存，`mmap` 会把文件全量计入峰值。页以 `shared_ptr` 管理，
  换出不会让调用方持有悬垂指针。
- 主键索引：磁盘 B+tree（`pk → RID`），页 0 为元数据页，叶子存 `(key, rid)`
  并维护 `next` 链（为将来的范围扫描预留）。插入走分裂上推，删除只摘除键、
  不合并节点（路由只需"最右且分隔键 ≤ key"的子页，因此仍然正确）。
  打开时直接加载元数据页，**不扫描堆文件**。

## 4. 向量索引方案

- 算法：自研 HNSW（M=32、efConstruction=200），不引入任何第三方向量索引库。
- `exact` 模式永远暴力扫描（SIMD 距离核），即使存在索引。
- `ann` 模式：
  1. 资格检查：索引存在、`build_key` 匹配、校准表存在；否则退化 `exact` 并记录原因。
  2. 小匹配集（`M ≤ threshold`）直接扫描候选集，等价精确。
  3. 大匹配集走过滤感知 HNSW：**不得"凑够 K 就停"**，必须满足「结果数 = K 且 ef ≥ 校准下限」，
     否则按倍增大 `ef`，仍不足则精确兜底。
- 校准：搜索从 `ef=256` 起，不足 k 条则翻倍，上限 2048；带过滤时按实测通过率
  放大 `ef`（约 1/选择性），避免 Accepted 集合过浅。
- 实测（10k × 128 均匀随机，120 查询）：无过滤召回 0.9992、过滤（10% 选择性）
  0.9892，均高于官方 0.95 门槛。
- 索引在打开时从堆文件重建，重建完成前不报就绪；回滚会把图标记为陈旧并在下次
  ann 查询前重建。

## 5. 事务处理

- M0：`BEGIN` 对整库做快照，`ROLLBACK` 还原，`COMMIT` 丢弃快照；
  每条数据修改语句前做整库快照，保证语句失败无部分生效。
- 计划 M3：物理 undo（前像）+ 行级 overlay，避免快照随数据量线性膨胀；
  允许脏页外刷（steal），大事务不会撑爆内存。

## 6. 提交持久化

```
修改页（缓存内，带属主事务号）
  → 提交时收集本事务的脏页，逐页分配 LSN 并写整页镜像到 WAL
  → 追加 COMMIT 记录
  → WAL fdatasync
  → 返回成功
  → 数据页之后按 LRU 惰性回写
```

- **no-steal**：页缓存拒绝逐出属主事务未提交的页，未提交字节不会进入数据文件，
  因此恢复无需 undo。
- 页头偏移 8 处的 LSN 记录该页最后一次镜像的日志位置，重放时按 LSN 比较保证幂等。
- 正常关闭：刷全部脏页并 fsync → 写 checkpoint → 截断 WAL。

## 7. 恢复流程

```
打开 WAL，扫描记录（CRC 失败/长度不全即视为尾部截断）
  → 收集有 COMMIT 记录的事务
  → 按日志顺序重放这些事务的页镜像（页 LSN < 记录 LSN 才写）
  → fsync 所有涉及的文件 → 截断 WAL
  → 打开堆文件与 B+tree → 必要时重建索引 → 打印就绪
```

重放直接作用在裸文件描述符上（早于任何页缓存建立），因此缓存不可能遮蔽日志镜像。

- 页头携带 `pageLSN`，redo 幂等，保证「恢复途中被强制终止」后再次启动收敛到同一状态。
- 向量索引可从持久化记录重建；重建完成前不得报告就绪。

## 8. 已实现功能（M0–M1）

- 持久化：catalog 原子写入、每表堆文件与 B+tree 索引、提交时刷脏页并 `fdatasync`、
  正常关闭回滚未提交事务。
- 主键索引：磁盘 B+tree，启动零扫描；插入时 upsert、删除摘键；构建标志保证恢复幂等。
- 完整 SQL 子集解析：`CREATE TABLE`、`INSERT`（多行）、`SELECT`（投影 / `*` / `L2_DISTANCE` /
  `WHERE` / `ORDER BY` / `LIMIT`）、`UPDATE`、`DELETE`、`BEGIN`/`COMMIT`/`ROLLBACK`。
- 类型校验：`BIGINT`、`VARCHAR(n)`（Unicode 码点计数）、`VECTOR(n)`（float32、拒绝 NaN/Inf/维度不符/溢出）。
- 语义：主键唯一、距离并列按主键升序、过滤后 TopK 在匹配集内计算、语句原子性、事务内读己写。
- 线格式：制表符分隔、可配置表头/分隔符/浮点格式/错误模板/就绪标识。
- 容器：多阶段构建，静态链接 `libstdc++`/`libgcc`，前台运行，无端口。

## 9. 已知限制

- 尚无 WAL：强制终止时正在刷写的页可能撕裂，恢复依赖页结构而非日志重放（M3）。
- B+tree 不做节点合并与回收，删除多时索引文件不收缩。
- 无向量索引，`ann` 模式尚未存在（M4）。
- 事务回滚依赖内存 undo 链：回滚需要的旧行镜像在事务期间驻留内存；
  这是 undo 的正常代价，但大事务下的内存上限尚未实测（M3 会给出有界策略）。
- 排序在内存中完成；超大结果集的 `ORDER BY` 未做外排（视题包用例决定是否实现）。
- 错误码沿用 MySQL 约定，待题包发布后按官方表重映射。

| 校准集 / 留出集分离，选参后冻结 | §4 的校准协议 |
