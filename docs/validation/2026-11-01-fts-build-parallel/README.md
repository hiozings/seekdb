# 全文索引采样与并行构建验证

基点为已发布的7301a84bf（按文档批处理）。最终选择默认DOP2策略，适配批量采样的真实词行与精确doc-id点查。参考[PR #2219](https://github.com/oceanbase/seekdb/pull/2219)并增加本分支批处理适配、compact采样隔离与扩展回归。官方基准输入、SQL、计时和评分文件均未修改。

## 同机测量

每组均为A/B/B/A/A/B六轮完整官方评测（每版本3次），相同CPU配置、内存2G、亲和性及官方参数。下面各组有各自基线，不能跨组混算。

| 对照 | 构建下降 | 分词下降 | 查询下降 | 三类等权下降 |
| --- | ---: | ---: | ---: | ---: |
| 7301 vs 并行候选，4核混合规格 | 11.699% | -5.866% | 6.294% | 4.042% |
| 原始5bce vs 并行候选，4核混合规格 | 26.913% | 43.946% | 70.795% | 47.218% |
| 7301 vs 并行候选，2核 | -0.374% | 0.406% | 0.151% | 0.061% |
| 原始5bce vs 并行候选，4个P核 | 27.481% | 29.785% | 72.081% | 43.116% |

混合规格四核为8/10/14/16；同规格P核为6/8/10/14；两核为8/10，客户端均固定12。CPU16的最高频率为4.1GHz且无SMT，其余所用P核为5.6–5.8GHz。每一组内部A/B的资源一致，完整配置和SHA见各目录runs.json/binaries.json。用户已分别授权相关governor临时调整，所有运行均记录恢复成功。

构建改善得到验证；分词和查询的跨组波动说明不能用某一组的本地分数代替正式平台成绩。当前完整原始版本对照仍未达到50%综合下降，不宣称满分。

## 未保留实验

- 并发缓存未命中合并：并发回归可将8次生成合并为1次，但完整构建平均退化5.796%，综合退化0.840%，已撤回。
- 四核默认DOP4：674项完整输出对照和原生回归通过，但相对DOP2构建退化9.002%、综合退化7.894%，已恢复DOP2。
- 短函数CPU采样存在时钟及嵌套开销；校准后的诊断只用于定位，未使用诊断二进制评分。

## 正确性

10个原生目标通过，包含DDL参数默认并行标志的初始化、assign、reset、序列化往返。674项完整输出覆盖五种分词器、分值/排序/布尔检索/DML、批边界，以及4096行乱序复合主键、分区表、显式hint/强制DOP/禁用并行/表DOP/索引DOP、ANALYZE和空表索引后DML。最终版本另运行9组原始官方SQL套件。

两核仍选默认DOP1；四核选择DOP2；有效显式并行设置保持原路径。采样只生成分片边界，不写compact collector。新的控制脚本模拟验证了部分governor设置失败及基准失败时的恢复，禁止未列入允许列表的路径和值。

最终交付源码恢复DOP2后重新编译，10/10原生目标及674项完整对照、9/9官方SQL再次通过。`candidate.binary.json`对应最终`fts-parallel-final`二进制。
